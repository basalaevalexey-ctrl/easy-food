# MVP Telegram-бота "AI счетчик калорий"

Дружелюбный Telegram-бот на Python 3.11, aiogram 3, SQLite и OpenAI API.

Бот принимает текст или фото еды, примерно считает калории и БЖУ, сохраняет запись в дневник и показывает прогресс за день.

## Возможности

- `/start` - приветствие и меню.
- После `/start` - предложение указать параметры для расчета цели.
- `/setup`, кнопка "Настроить цель" или "Изменить цель/параметры" - пошаговая настройка профиля.
- Текстовое добавление еды: `2 яйца, творог 200 г, банан`.
- Фото еды с примерной оценкой через OpenAI Vision.
- Если сообщение или фото не похожи на еду, бот ничего не записывает и предлагает открыть инструкцию.
- Корректировка записи: порция меньше, порция больше, указать граммы, удалить.
- Ежедневные напоминания в выбранное время, пока бот запущен.
- Мотивационные пуши для пользователей с целью и серией активности.
- Ням-стрик: день засчитывается после первой записи еды, хранится в профиле пользователя и не зависит от калорий.
- Ачивки: первые записи, фото еды, стрик, полный день и попадание в дневную цель.
- Ежедневные миссии: одна мягкая задача на день, показывается в `/mission`, `/today` и напоминаниях.
- Реактивационная цепочка для пользователей, которые нажали `/start`, но еще не добавили еду и не начали настройку цели.
- `/today` или "Сегодня" - прогресс за текущий день.
- `/history` или "Дневник" - последние 7 дней.
- `/help` или "Инструкция" - подробная инструкция по работе с ботом.
- `/admin` - админ-панель с метриками за сегодня, 7 дней и все время: старты, цели, фото, текстовые обращения, пользователи и записи еды.
- `/stats` - статистика только для админов из `ADMIN_IDS`.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env` и заполните значения:

```env
BOT_TOKEN=123456:telegram_bot_token
OPENAI_API_KEY=sk-...
ADMIN_IDS=123456789,987654321
OPENAI_MODEL=gpt-4o-mini
DATABASE_PATH=/app/data/calories.sqlite3
AUTO_PUSH_TIME=19:00
APP_TIMEZONE=Europe/Moscow
PORT=8080
WEBAPP_URL=
WEB_SESSION_SECRET=replace-with-a-long-random-value
VKID_CLIENT_ID=
VKID_CLIENT_SECRET=
VKID_REDIRECT_URI=https://app.nyammetr.ru/web/auth/vk/callback
```

`ADMIN_IDS` можно оставить пустым, если команда `/stats` не нужна.

`DATABASE_PATH` задает место хранения SQLite-базы. Для BotHost используйте путь внутри видимой папки приложения:

```env
DATABASE_PATH=/app/data/calories.sqlite3
```

На BotHost путь `/data/calories.sqlite3` может очищаться при редеплое. Если он указан, бот автоматически переедет на `/app/data/calories.sqlite3` и попробует скопировать старый файл из `/data`, если он еще доступен.

Бот также держит backup-копии SQLite в нескольких известных местах и при запуске выбирает файл с наибольшим количеством данных. Это защищает от ситуации, когда после редеплоя один из путей оказывается пустым.

`DATABASE_BACKUP_PATHS` - дополнительные резервные SQLite-файлы через запятую. На новом хостинге указывайте только пути внутри подтверждённого постоянного volume.

`DATABASE_REQUIRE_EXISTING=true` запрещает запуск бота без существующей корректной SQLite-базы. Параметры `DATABASE_MIN_USERS`, `DATABASE_MIN_ENTRIES` и `DATABASE_MIN_EVENTS` дополнительно запрещают старт, если в загруженной базе меньше ожидаемого количества данных.

`BACKGROUND_JOBS_ENABLED=false` отключает напоминания, реактивационные цепочки и недельные отчёты. Используйте этот режим на тестовом экземпляре во время миграции.

`TELEGRAM_POLLING_ENABLED=false` запускает только web/API часть и не забирает обновления Telegram, не меняет меню бота и не конфликтует со старым polling-экземпляром. В этом режиме `BACKGROUND_JOBS_ENABLED` также обязан быть `false`.

`INSTANCE_NAME` выводится в логах и `/health`, чтобы отличать старый, тестовый и боевой экземпляры.

`AUTO_PUSH_TIME` - время ежедневного мотивационного пуша для пользователей с целью, которые были активны два дня подряд, но еще не заходили сегодня.

`APP_TIMEZONE` - таймзона, по которой считаются напоминания, дни дневника, миссии и стрики. Для Москвы оставьте `Europe/Moscow`.

`PORT` - порт встроенного web-сервера миниаппа. Для Relaxdev используйте `8080`.

`WEBAPP_URL` - публичная ссылка миниаппа, которую выдает BotHost. Когда она задана, бот добавляет кнопку "Открыть Нямметр" и кнопку меню Telegram.

`WEB_SESSION_SECRET` - отдельный длинный случайный секрет для подписания браузерных сессий. На production задайте не менее 32 случайных символов и не публикуйте значение. Если переменная не задана, используется производный ключ от `BOT_TOKEN`.

`VKID_CLIENT_ID`, `VKID_CLIENT_SECRET` и `VKID_REDIRECT_URI` включают вход через VK ID. Создайте Web-приложение в кабинете VK ID и добавьте точный callback `https://app.nyammetr.ru/web/auth/vk/callback`. Пока `VKID_CLIENT_ID` или callback не заданы, кнопка VK скрыта.

## Веб-версия

Полный интерфейс Нямметра доступен по пути `/web` и использует ту же базу и API, что Telegram Mini App. Доступны вход через Telegram, VK ID и регистрация по email/паролю. Пароли хешируются через `scrypt`, а браузер получает защищённую `HttpOnly` cookie-сессию. Внешние профили хранятся в `external_identities`, email-учётные данные — в `email_credentials`, а дневник, цели, вода, миссии и достижения используют общие таблицы приложения.

Для восстановления пароля настройте SMTP-переменные `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`, `SMTP_FROM_NAME`, `SMTP_USE_SSL` и `SMTP_USE_TLS`. `PUBLIC_WEB_URL` должен указывать на `https://app.nyammetr.ru/web`. Ссылки восстановления одноразовые и действуют 30 минут; в базе сохраняется только хеш токена.

Для production:

1. Направьте `https://nyammetr.ru/web` на web-инстанс Нямметра.
2. В `@BotFather` выполните `/setdomain`, выберите бота и укажите `nyammetr.ru`.
3. Задайте `WEB_SESSION_SECRET` на bot- и web-инстансах одинаковым значением.
4. Откройте `https://nyammetr.ru/web` и проверьте вход, выход и существующий дневник.

Telegram Login проверяется сервером по подписи и принимается только в течение 10 минут после выдачи. Браузерная сессия действует 30 дней.

`ADMIN_TOTAL_BASELINE` и `ADMIN_TOTAL_BASELINE_OFFSET` можно использовать, если хостинг потерял SQLite-базу и нужно зафиксировать последнюю известную общую статистику. Это JSON-объекты с числовыми значениями; обычно их можно оставить пустыми.

## Запуск

```bash
python -m app.bot
```

При первом запуске создастся файл базы по пути из `DATABASE_PATH`. По умолчанию это `data/calories.sqlite3`.

Если раньше бот уже работал с базой `calories.sqlite3` в корне проекта, при первом запуске новая версия автоматически скопирует ее в новый путь из `DATABASE_PATH`, если там еще нет базы. Текущий прогресс пользователей сохранится.

Перед переносом на RelaxDev используйте чек-лист [RELAXDEV_MIGRATION.md](RELAXDEV_MIGRATION.md).

## База данных

SQLite создает две таблицы:

- `users` - профиль, цель, дневная норма калорий и белка.
- `food_entries` - записи еды с калориями, БЖУ, источником и временем.

## Примечания

Оценки еды примерные, особенно по фото. Бот не является медицинской рекомендацией и не заменяет врача.
